# Поддержка через Telegram

Система поддержки сохраняет обращения в Supabase. Сообщения пользователя отправляются в Telegram владельца, а ответ владельца должен быть отправлен ответом на сообщение бота. Ключи используются только серверными Vercel Functions.

## Переменные Vercel

Добавь как Sensitive-переменные в Production:

- `SUPABASE_SERVICE_ROLE_KEY` — серверный service-role ключ проекта Supabase; не публиковать в браузере.
- `TELEGRAM_BOT_TOKEN` — токен Telegram-бота от BotFather.
- `TELEGRAM_OWNER_CHAT_ID` — числовой chat id владельца, которому бот отправляет обращения.
- `TELEGRAM_WEBHOOK_SECRET` — случайная длинная строка для заголовка webhook.

Публичному клиенту по-прежнему нужны только `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` и URL поддержки `VITE_SUPPORT_API_URL` (`https://opacucumlgwmhgjonhhe.supabase.co/functions/v1/api/support` для GitHub Pages - вход через функцию на Supabase, которая передаёт запрос на Vercel).

## Webhook

После деплоя задай webhook URL:

`https://homework-copilot-taupe.vercel.app/api/telegram-webhook`

Именно этот адрес, а не `www.homeworkcopilot.ru/api/...`: фронт раздаёт GitHub
Pages, и маршрута `/api/*` там не существует. Тот же адрес зашит в
`server/support.ts` (`ensureTelegramWebhook`).

Руками ставить его не нужно: проверка здоровья в cron админки раз в пять минут
смотрит `getWebhookInfo` и ставит webhook заново, если его нет, адрес чужой,
не хватает `message`/`callback_query` или наш обработчик отвечает 401/403 после
смены секрета. То же - перед отправкой новой идеи; сбой там идею не задерживает.
Итог виден в админке: «Мониторинг», плитка Telegram. Без
`TELEGRAM_WEBHOOK_SECRET` плитка жёлтая: уведомления уходят, ответы - нет.

Endpoint принимает только POST, проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`, чат владельца и связь `reply_to_message` с сохранённым сообщением бота. Нерелевантные сообщения игнорируются.

`TELEGRAM_OWNER_CHAT_ID` - личный чат с ботом, не группа: кнопки идей принимают
нажатие только от этого id. Уведомление правила «Новый тикет» в Telegram
выключено (20260913100200): само обращение уже пришло сообщением, на которое
можно ответить.

Новое обращение с идеей приходит с кнопками «Да, хорошая идея» и «Нет». Кнопки используют короткий непрозрачный токен, который сверяется с серверной привязкой сообщения. Одобрение только открывает ручной выбор суммы в админке и само ничего не начисляет. Альтернатива кнопке — ответ владельца точной фразой «да это хорошая идея» с допустимой нормализацией регистра, пробелов и пунктуации. Фразу разбирает база (`private.normalize_support_idea_approval`), а не вебхук.

Платежи пока не подключены: обращения по оплате показывают владельцу текущий баланс и историю внутреннего баланса, но автоматический возврат не выполняют.
